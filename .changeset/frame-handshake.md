New SDK option `dashboardOrigins: string[]` (#59). When the page is framed, `init()` posts `{ type: "heat-tracker:frame-hello", href: origin + pathname }` (no query or hash) to each listed origin, with that origin as the exact `targetOrigin`, never `*`. Without the option nothing is sent. The reference dashboard uses this handshake instead of the iframe's `load` event, which Chromium fires for its own error page: its onboarding snippet fills in `dashboardOrigins` with the dashboard's origin. The dashboard accepts a hello only from the iframe's window and from the page's origin or an allowlisted one. Framing blocked by `X-Frame-Options` or CSP, as detected by the server check, shows `HEAT_E_FRAME_BLOCKED` at once. An inconclusive check without a valid hello within 8 s shows `HEAT_E_FRAME_NO_RESPONSE` ("This page didn't respond. Check that the heat-tracker snippet is installed with this dashboard in `dashboardOrigins`, and that the site allows framing.") with an "Open page in new tab" link. A hello from another host or path shows `HEAT_E_FRAME_REDIRECTED` and hides the heatmap. The dashboard sends `Content-Security-Policy: frame-src` restricted to `HEAT_DASHBOARD_SITE_ORIGINS`. `DASHBOARD_ERRORS` gains `HEAT_E_FRAME_NO_RESPONSE` and `HEAT_E_FRAME_REDIRECTED`; `docs/errors.md` includes them.
